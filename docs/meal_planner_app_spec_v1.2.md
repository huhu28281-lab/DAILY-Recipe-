## 1. 무엇을 만드는가

일주일 아침·저녁 식단을 자동으로 짜주는 가정용 앱.

세 가지를 한다.
1. 냉장고에 있는 재료를 먼저 쓰는 식단을 만든다
2. 끼니마다 **추가로 드는 돈**을 보여줘서 할지 말지 정하게 한다
3. 인원수에 맞춰 계량이 바뀌는 레시피를 준다

### 설계 원칙 4개

| 원칙 | 뜻 |
| :--- | :--- |
| **LLM은 메뉴만** | 무엇을 먹을지는 AI가, 얼마인지·몇 kcal인지는 DB가 정한다 |
| **알레르기 무관용** | 알레르기 재료가 든 메뉴는 사용자 화면에 도달하지 않는다 |
| **입력은 최소** | 재료 3개만 골라도 식단이 나온다. 나머지는 전부 선택 |
| **추정은 추정으로** | 금액은 `약 9,800원`. 정확한 척하지 않는다 |

## 2. 계산 기준

> 이 장이 다른 서술과 충돌하면 이 장이 이긴다.

### 2.1. 칼로리 기준

kcal을 담는 모든 필드·라벨·변수는 접미사를 갖는다. 접미사 없는 kcal은 버그로 취급한다.

* `_per_person` — 1인분 (메뉴 카드, 레시피)
* `_household` — 가구 합계 (리포트, 목표치)

**끼니 배분:** 아침 25% / 점심 40% / 저녁 35%. 앱이 관리하는 건 **아침+저녁 60%** 뿐이다.

**참조 케이스 (3인 가구, 테스트 픽스처로 사용)**

| 구성원 | 하루 | 아침 | 저녁 | 아침+저녁 |
| :--- | ---: | ---: | ---: | ---: |
| 성인 남성 | 2,400 | 600 | 840 | 1,440 |
| 성인 여성 | 1,900 | 475 | 665 | 1,140 |
| 청소년 남 | 2,700 | 675 | 945 | 1,620 |
| **가구 합계** | **7,000** | **1,750** | **2,450** | **4,200** |

구성원 기준값은 한국인 영양소 섭취기준(KDRIs) 내장 테이블 × 활동량 계수(적음 0.9 / 보통 1.0 / 많음 1.15).

### 2.2. 냉장고 활용 지표

| 지표 | 산식 | 목표 |
| :--- | :--- | :--- |
| `pantry_coverage_rate` | 보유로 충당된 품목 수 ÷ 총 필요 품목 수 | ≥ 0.60 |
| `expiry_priority_rate` | 임박(D-3) 재료 중 배치된 비율 | ≥ 0.90 |

양념류(`is_staple: true`)는 분모에서 제외한다. 포함하면 지표가 부풀려진다.

UI의 `집에 있는 재료로 100%` 배지는 **그 끼니 하나**의 coverage가 1.0일 때만 쓴다.

### 2.3. 영양 목표

기준: KDRIs 에너지 적정비율 — 탄 55~65 / 단 7~20 / 지 15~30%.

| 프로파일 | 탄 | 단 | 지 |
| :--- | ---: | ---: | ---: |
| **표준 (기본값)** | 58 | 18 | 24 |
| 성장기 강화 | 55 | 20 | 25 |
| 체중 감량 | 50 | 25 | 25 |
| 혈당 관리 선호 | 50 | 20 | 30 |

판정은 **주간 평균**으로만 한다. 하루 편차는 정상이므로 경고하지 않는다.
체중 감량 선택 시 단백질이 권장 상한을 넘으므로 고지 문구를 띄운다.

### 2.4. 비용 기준 ★ v1.2 핵심

**세 숫자를 구분한다.** 이름을 섞으면 화면마다 금액이 달라 보인다.

| 이름 | 계산 | 표시 위치 |
| :--- | :--- | :--- |
| `meal_extra_cost` | **구매 필요 재료만** × 단가 (필요량 비례 배분) | 끼니 카드, Swap 후보 |
| `meal_total_cost` | 보유 재료 포함 전체 원가 | 레시피 상세(참고용) |
| `grocery_total_cost` | **포장 단위 올림** 후 합계 | 장보기 견적서 |

**규칙**
* 끼니 카드에 보여주는 건 `meal_extra_cost`다. 집에 있는 재료는 0원으로 친다. 안 해도 굳는 돈이 아니면 판단 근거가 못 된다.
* `is_staple: true` 재료(간장·참기름·소금 등)는 끼니 비용에서 **제외**한다. 숫자만 지저분해지고 판단에 도움이 안 된다.
* 끼니 합계와 장보기 총액은 **다른 게 정상**이다. 소고기 400g이 필요해도 마트는 600g 팩으로 판다. 견적서에 한 줄 고지:
  > 마트 포장 단위 기준이라 끼니별 합계보다 클 수 있어요.
* 표기는 백 원 단위 반올림 + `약`. `9,847원` ❌ → `약 9,800원` ⭕
* 가격 미확인 재료가 섞이면 `약 9,800원+`로 표기해 빠진 게 있음을 드러낸다.

**가격 출처:** KAMIS(농산물유통정보) / aT 참가격 등 공개 시세 + 내부 보정 테이블. 주 1회 배치 갱신. **LLM은 금액을 생성하지 않는다.**

**한계 고지 (견적 화면 하단 고정)**
> 공개 시세 기준 추정치입니다. 지역·판매처·시기에 따라 다를 수 있어요. 세일가는 반영되지 않습니다.
> 출처 KAMIS · 기준일 2026-09-06

## 3. 입력 최소화 설계 ★ v1.2 신설

가정에서 주말 5분 쓰는 앱이다. 첫 화면에서 요구하는 게 많으면 나간다.

| 항목 | 기본 동작 | 자세한 설정 |
| :--- | :--- | :--- |
| 재료 수량 | 탭만 하면 마스터의 기본 포장 단위로 자동 (계란→10알, 두부→1모) | 탭 길게 눌러 수정 |
| 유통기한 | 입력 안 해도 됨. 가중치 중립 | `곧 상해요` 버튼으로 D-day만 지정 |
| 알레르기 | **없음이 기본.** 검색창으로 찾아 추가 | 22종 전체 목록은 `모두 보기` 안에 |
| 활동량 | 보통 고정 | `더 정확하게` 펼치면 3단 선택 |
| 영양 프로파일 | 표준 고정 | 위와 동일 |
| 민감정보 동의 | 온보딩에 없음 | **알레르기를 처음 입력하는 순간** 시트로 노출 |

**최소 경로 보장:** 구성원 수만 정하고 재료 3개를 탭하면 식단이 나온다. 그 밖의 모든 입력은 선택이다.

**첫 실행 흐름**
```
[1] 몇 명이 함께 드세요?   → [1인] [2인] [3인] [4인+]
[2] 냉장고에 뭐가 있나요?  → 자주 쓰는 재료 20개 그리드, 탭해서 켜기
[3] 식단 만들기
```
연령·성별은 [1]에서 인원만 고르면 성인 기준으로 잡고, 나중에 가족 탭에서 조정한다.

## 4. 기능 명세

### 4.1. 가족 프로필

* 구성원: 연령대(영유아/어린이/청소년/성인/고령자), 성별, 활동량. 최대 8인.
* 알레르기: **식약처 표시 대상 22종** — 난류, 우유, 메밀, 땅콩, 대두, 밀, 잣, 호두, 게, 새우, 오징어, 고등어, 조개류(굴·전복·홍합), 복숭아, 토마토, 닭고기, 돼지고기, 쇠고기, 아황산류, 아몬드, 참깨, 옥수수
  * 서버 설정(`allergen_master`)에서 로드한다. **하드코딩 금지** — 고시 개정으로 바뀐다.
* 목표 칼로리는 §2.1 규칙으로 자동 산출. 구성원 변경 시 실시간 갱신.

### 4.2. 식재료 보관함

* 보유 재료: 재료명 / 수량+단위 / 유통기한(선택) / 카테고리
* D-3 이내 자동 `is_priority` 플래그, 배치 가중치 3.0
* 구매 예정(위시리스트) 가중치 2.0
* 제철 재료: 시스템 월 기준 큐레이션 + 보완 영양소 사유 표시
* **재고 차감 원장(ledger):** 끼니 순서대로 수량을 차감한 잔량 배열을 만든다.
  * 계란 10알 → 월 아침 2알 → 잔량 8알 → 수 아침 3알 → 잔량 5알
  * 잔량이 음수가 되는 배치는 거부한다 (검증 V-04)
  * 분할 재료(두부 0.5모)의 잔여분은 같은 주 안에 배치되도록 가중치 2.5

### 4.3. 식단 생성

* 월~일 아침 7 + 저녁 7 = **14끼니**
* 아침 조리 15분 이하 / 저녁 **30~40분**
* 주말 점심 옵션(기본 OFF, ON 시 16끼니)
* 다양성: 동일 주재료 연속 3끼니 금지 · 동일 메뉴 주간 중복 금지 · 최근 4주 이력 중복률 30% 이하

### 4.4. 끼니별 비용 ★ v1.2 신규

끼니 카드에 `meal_extra_cost`를 표시한다.

```
🌙 저녁                        [🔄 변경]
+------------------------------------+
| 소고기 뭇국 & 삼겹살 구이          |
| ⏱35분 · 740 kcal/1인분 · 난이도 중 |
| 🛒 추가 지출 약 9,800원            |
+------------------------------------+
```

* 집에 있는 재료만으로 되는 끼니는 금액 대신 `✓ 집에 있는 재료로 100%`
* 가격 미확인 재료 포함 시 `약 9,800원+`

### 4.5. 끼니 교체 (Swap)

단순 셔플이 아니라 **부분 재생성 트랜잭션**이다.

1. 대상 끼니를 원장에서 제거, 점유 재고 반환
2. 후보 필터: 알레르기(V-01) · 조리시간(V-02) · 다양성(V-03) · 재고 음수(V-04)
3. **후보 5개를 비용·냉파율과 함께 제시** — 이게 Swap의 핵심 가치다

```
어떤 걸로 바꿀까요?

┌ 두부 김치찌개 ──────────────┐
│ ⏱25분 · ✓ 집에 있는 재료로 100% │
│ 추가 지출 0원          [선택] │
└──────────────────────────┘
┌ 닭볶음탕 ──────────────────┐
│ ⏱40분 · 🛒 추가 지출 약 6,200원 │
│                        [선택] │
└──────────────────────────┘
```

4. 선택 시 재고 원장 전체 · 구매 목록 · 견적 · 영양 지표를 **모두 재계산**하고 다양성 규칙을 재검증한다
5. 변경 요약 토스트: `바꿨어요. 살 것 2개 추가, 예상 금액 +3,200원`
6. 주당 20회 제한 (LLM 호출 비용)

### 4.6. 레시피 — 인분 스케일링

**일괄 곱셈 금지.** 4배 하면 짜진다.

| 재료군 | 함수 |
| :--- | :--- |
| 주재료(육류·채소·곡류) | `q × n` |
| 양념(소금·간장·고추장) | `q × n^0.75` |
| 국물·물 | `q × n^0.85` |
| 기름(볶음) | `q × n^0.7` |
| 향신·허브 | `q × n^0.6` |

* 조리시간은 비례하지 않는다. 별도 보정 테이블 참조 (국물 2인→4인 +5분, 볶음은 **나눠 조리** 안내)
* 실사용 단위로 반올림: `0.75큰술` → `1/2큰술 + 1작은술`, `137g` → `140g`
* 비선형 환산임을 ⓘ 한 줄로 안내한다. 안 하면 계산이 틀렸다고 오해한다.
* 타이머: 시간 표현 파싱 성공 단계에만 칩 노출. **실패 시 숨긴다** — 틀린 타이머보다 없는 게 안전하다.

### 4.7. 이력·내보내기

* 주간 식단 12주 보관, 주 단위 조회
* 끼니 좋아요/싫어요 → 다음 주 가중치(좋아요 1.5 / 싫어요 0.2), 싫어요 3회 누적 시 후보 풀 제외
* 텍스트 / PNG / PDF 내보내기

## 5. 생성 파이프라인

```
[1] 입력 정규화
    프로필 + 재고(수량·유통기한) + 위시리스트 + 제철
    → 표준 ingredient_id 매핑, 알레르기 유니온 산출
          ↓
[2] 제약 사전 계산
    금지 재료, 끼니별 시간 상한, 임박 재료 우선순위 큐
          ↓
[3] LLM 메뉴 생성 (JSON 스키마 강제)
    ※ 가격·칼로리 필드 생성 금지
          ↓
[4] 검증 가드 — 실패 시 [3] 재호출, 최대 3회
          ↓
[5] 수치 채우기
    영양 DB → kcal·영양소   |   가격 DB → 끼니별·주간 비용
          ↓
[6] 지표 산출 및 응답
```

### 검증 가드

| ID | 규칙 | 실패 시 |
| :--- | :--- | :--- |
| **V-01** | 알레르기 유니온 재료가 어떤 끼니에도 없을 것 | 끼니 폐기 후 재생성. 3회 실패 시 중단 + 안내 |
| **V-02** | 아침 ≤15분, 저녁 ≤40분 | 재생성 |
| **V-03** | 연속 3끼니 주재료 중복 금지, 주간 메뉴 중복 금지, 4주 이력 중복 ≤30% | 재생성 |
| **V-04** | 재고 잔량 음수 금지 | 초과분을 `purchase`로 전환 후 통과 |
| **V-05** | 모든 재료가 유효한 `ingredient_id`를 가질 것 | 퍼지 매칭 → 실패 시 재생성 |

**V-01은 어떤 경우에도 우회하지 않는다.** 판정은 재료명 문자열이 아니라 `ingredient_id → allergen_tags` 매핑으로 한다. 가공식품의 숨은 원료를 문자열로는 못 잡는다.

### 실패 폴백

3회 실패 또는 타임아웃 시 사전 큐레이션 템플릿 식단(알레르기 조건별 12종)에서 조건에 맞는 것을 제공한다.
UI에 **`기본 추천 식단` 배지를 노출**한다. 폴백임을 숨기지 않는다.

## 6. AI 프롬프트

```
[Role]
너는 한국 가정식 기반 주간 식단 설계 엔진이다. 너의 출력은 자동 검증기를 통과해야 한다.

[Absolute Constraints — 위반 시 출력 전체가 폐기된다]

### 9.2. 타이포

**폰트:** Pretendard (fallback SUIT, -apple-system, Roboto). 둘 다 SIL OFL. 고정폭 숫자 활성화.

| 계층 | 크기 | 행간 | 두께 |
| :--- | ---: | ---: | :--- |
| Display | 28 | 36 | Bold 700 |
| H1 | 22 | 30 | Bold 700 |
| H2 | 18 | 26 | SemiBold 600 |
| Body L | 16 | 24 | Regular 400 |
| Body M | 14 | 20 | Regular 400 |
| Caption | 13 | 18 | Medium 500 |

* 자간 상한 −0.2px. Pretendard 한글에 −0.5px는 과하다.
* Caption 13px. 칼로리·금액이 핵심 정보인데 12px는 최소 권장 이하다.
* **동적 타입:** `sp`/`scaledFont`로 구현, 배율 0.85×~1.6× 지원. 1.3× 이상에서 끼니 카드 메타 정보를 가로→세로 배치로 전환한다. 잘림(`ellipsis`)은 메뉴명에만 허용하고 **수치·금액·경고 문구는 절대 자르지 않는다.**

### 9.3. 레이아웃

8pt 그리드. 좌우 마진 16px / 카드 패딩 16~20px / 카드 간 12px / 섹션 간 24~32px.
곡률: 칩 999px, 버튼 12px, 카드 16px, 바텀시트 24px.
**터치 타깃 48×48px 이상**, 인접 간격 8px 이상. 칩 시각 높이가 32px여도 터치 영역은 상하 8px 확장한다.

### 9.4. 모션

* 칩 토글 150ms `ease-out`, `scale 0.95→1.0` + `lightImpact`
* 바텀시트 스프링 `damping 0.8 / stiffness 300`
* Swap 결과 크로스페이드 250ms + 요약 토스트 2.5초
* **Reduce Motion 켜짐 시** 모든 스케일·스프링·슬라이드를 즉시 전환 또는 단순 페이드로 대체. Lottie는 정지 이미지로.

```

### 생성 중 / 실패

**생성 중** — 진행 문구는 실제 파이프라인 단계에 대응시킨다. 가짜 퍼센트를 쓰지 않는다.
```
      (Lottie: 김이 나는 냄비)
      식단을 만들고 있어요

  ✓ 가족 3명의 목표를 계산했어요
  ✓ 곧 상하는 두부부터 배치했어요
  ● 알레르기 재료를 확인하는 중...
  ○ 장보기 금액을 계산하는 중
            [ 취소 ]
```

**실패**
```
  조건에 맞는 식단을 만들지 못했어요
  제외 조건이 많아 고를 수 있는 메뉴가 부족합니다.

  [ 기본 추천 식단 보기 ]
  [ 조건 바꾸러 가기 ]
  [ 다시 시도 ]
```
* 부분 실패 시 성공한 끼니는 그대로 두고, 실패 자리에만 안내 카드를 넣는다.
* "오류가 발생했습니다" 같은 문구는 쓰지 않는다. 원인을 구체적으로 쓴다.

## 11. 만드는 순서
